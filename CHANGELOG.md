- Bumped Curve It to **V3_11** for **Multicolor Split** and the **DiLiuLab palette** below. Both reach into Curve It itself, not only into companion tools: the **Other tools** panel gains a fourth row and a `multicolor_split` help topic, `main()` gains the hidden `--multicolor-split` pass-through, **View curve** and **Convert XYZ...** each gain a **Palette** menu, and `--convert-color` accepts a palette name.
- Added the **DiLiuLab palette** as an option in every tool that tells components, chains, parts or plotted quantities apart by colour. It is the lab's nine figure colours from gr_colors, https://github.com/DiLiuLab/gr_colors, in the lab's order, red, blue, magenta, cyan, orange, purple, green, yellow and mint green, together with their tint-matched neutral, black at T100 and gray below, each at the lab's five tint levels T100, T80, T60, T40 and T20, where T mixes toward white. The colours are stored once, in the new `assets/diliulab_colors.json`, and read through one new module, `curve_it_lib/lab_colors.py` v1.0, so no tool carries a copy of the lab's hex values; a script outside the package can read the JSON as it stands or call `lab_colors.lab_colors("T80")` and `lab_named_colors()`. `python3 curve_it_lib/lab_colors.py` prints every tint, `--tint T80` prints one, and `--write-asset` regenerates the file; a tint it does not hold, `inf` and `nan` included, and a `--write-asset` path that cannot be written are usage errors, the tint refused before anything is printed. Every tool imports the reader softly, the way it already imports `vect_io.py`, relative and then flat inside `curve_it_lib/` and from the package in `curve_it.py`, so a missing `lab_colors.py` costs the palette and nothing else: each menu then offers only its first entry, `default` (`custom` in Convert XYZ...), and any other `--palette` is refused with the missing file named. `vect_io.py` catches any failure of that import, not only a missing file, because Interpolate, total curvature/writhe and Get phase, which import it just to read VECT, would otherwise stop at startup on a `lab_colors.py` that cannot load, a half-synced copy with a syntax error for one, and Curve It would report `vect_io.py` missing on every VECT file.
- Generated the asset from gr_colors V3.3's own formula rather than copying colours out of a figure, and measured it against both forms gr_colors publishes. Hue `i` is `i * 0.618033988749895 mod 1` from a start of 0, at saturation 0.67 and value 0.90. The lab's colours are indexes 0, 1, 3, 4, 5, 6, 7, 10 and 12, and tint T mixes toward white as `round(T * c + (1 - T) * 255)`, gr_colors' own rounding; the neutral is black mixed the same way. The T100 row equals the nine-row table in the gr_colors README hex for hex. All five tints equal the colour lists gr_colors ships, `grcT100.clr` to `grcT20.clr`, swatch for swatch: ten swatches each, neutral included, read back through AppKit's `NSColorList` in the lists' own sRGB space. T80, for example, is `#eb7070 #7094eb #eb70db #70ebd6 #ebb270 #8e70eb #75eb70 #e1eb70 #70ebad` with gray `#333333` in both. The asset on disk is byte-for-byte what `--write-asset` writes, and a missing or unreadable asset makes the reader fall back to the formula, so the option never disappears. So does valid JSON of the wrong shape, as a hand edit can leave it: a list or other non-object, a colour or neutral that is not an object, a colour with no name, or tints that are not labels such as `T80` or leave out `T100`. Without that check such a file raised from `palette_choices()`, which every window calls while it is being built.
- Kept Curve It independent of gr_colors: nothing in the package imports, runs or reads the gr_colors script. The colours live in the asset, the fallback formula is `lab_colors.py`'s own code, and `tests/test_lab_colors.py` compares both against all fifty values recorded from gr_colors V3.3 on 2026-09-26, nine colours and the neutral at five tints, rather than importing `gr_colorsV3_3.py` from a sibling checkout as its first draft did. Two guards keep it that way: one scans every source file for an import of, a script name from or a path into gr_colors, and one imports every tool that offers the palette with any `gr_colors` import made to fail and still gets the T80 colours, from the asset and from the fallback alike. A gr_colors checkout is therefore never needed, and a later gr_colors release cannot change these colours; adopting new lab colours means editing or regenerating the asset.

- Added **Multicolor Split** at `curve_it_lib/multicolor_split.py`, v1.4.0, which splits the chains of a PDB or mmCIF model into separate ChimeraX `molmap` solids, one STL per colour for a multi-material printer, that tile the whole molmap surface exactly. The method and its validation are unchanged from v1.3.0. What v1.4.0 adds is the window's help, its icon, a window that grows to fit its contents but never past the screen, and `self_command()` for the one-file pass-through; the launcher and the pass-through itself are new in `curve_it.py`, all described below. A part is one chain or several joined by a comma, given in peeling order, so `--parts A C` makes two colours and `--parts A,B C` gives A and B one colour between them; by default every chain is its own part. A run writes `<tag>_p1_chainA.stl`, `<tag>_p2_chainC.stl` and so on in one shared frame, `<tag>_whole.stl` for reference only, `<tag>_report.txt` and `.json`, `<tag>_preview.png` and `.glb`, and `<tag>_work/` holding the ChimeraX jobs and logs, the tag and the default output folder both being `<structure stem>_molmap<resolution>_split`. The STLs, reports and previews are staged, and only once the report is complete does a re-run with the same tag move that tag's previous set into `_previous_<timestamp>/`, then move the new files in, with the logs following into `<tag>_work/`, so the folder never holds two runs' files mixed.
- Tiled the parts exactly rather than contouring each one on its own, because two solids built from fields independently do not meet: they leave a void about 0.25 Angstrom wide between them, and at 1:1 that prints as a visible groove along every colour boundary. On the pinned switchback666 example below, the two field-built solids come to 1.2397 % less than the whole, a 126.0 Angstrom^3 void worth 0.238 Angstrom of mean clearance across a 530.6 Angstrom^2 interface. So only one side of each boundary is built from a field and the other is its exact `manifold3d` complement, peeled in part order: `P_1 = whole & F_1`, each later part is what remains intersected with its field against the *later* parts only, and the last part is the remainder, which hands every void strip to the neighbour whose territory it lies in. The earlier part of each pair therefore carries the field-built face, and the colour boundary sits about 0.1-0.2 Angstrom into it, 0.1-0.2 mm at 1:1, which the report states; reordering `--parts` chooses which side takes it. Boolean fragments left along the colour boundaries, anything under 4 voxels (0.5 Angstrom^3 at grid 0.5), are handed to the neighbouring part they share the most surface with. They are not confined to where three parts meet: the two-part example below hands 3 of them, 0.0035 Angstrom^3 in all, from P2 to P1. So the tiling stays exact without pits, and sealed cavities stay cavities.
- Defined each part's ownership field as `F = T - K * max(max_rivals M_j - M_k, 0)` inside the whole (`T >= L`) and `F = T` outside it, `T` being one molmap of all the selected chains and `M_k` one per part on the same grid (`onGrid`, 0.5 Angstrom by default). molmap Gaussians add, so `T` equals the sum of the part maps, which is checked on every run and holds to about `3e-7`. `F` is `T` wherever part k is densest and drops steeply below the contour level across the medial surface to a rival, so marching cubes interpolates a smooth sub-voxel cut face. Inside the whole this is bit-identical to ChimeraX's `volume subtract` / `volume threshold minimum 0 set 0` / `volume add scaleFactors 1,-K` chain; confining it to the inside is a deliberate departure, because applied everywhere the penalty also pulls the field-built skin inside the whole's skin wherever the part owns the surface, and the complement inherits a wrong-colour film there, 2-20 Angstrom^3 per model at 4 Angstrom and detached flakes at 3 Angstrom and below. `K = 16` is a slope per voxel, valid at resolution 4 and grid 0.5: in the sweep it was validated on, below about 12 the field-built parts interfered and at 20 or more marching cubes tore, though another model can differ, and the switchback666 example below gives clean fields for every K from 8 to 24. At any other resolution or grid it is rescaled to its per-voxel equivalent `K0 = 16 * (res/4) * (0.5/grid)` and confirmed by a scan in which the clean candidate nearest `K0` wins, so `--resolution 3.7` runs at 14.8; K moves the colour boundary by hundredths of a millimetre. The 0.5 Angstrom grid is not a detail either: at molmap's own default grid, resolution/3, the colour interface cannot be resolved finer than about 1 mm whatever else is done.
- Pinned the contour level by a scan and never inherited it. The candidates run from the guess minus 0.008 to the guess plus 0.008 in 0.002 steps (`--level-span`, `--level-step`), the guess being molmap's own automatic level, the contour that encloses 95 % of the map's density, rounded to three decimals unless `--level-guess` gives one. A level is accepted only when the whole and every part's own field-built solid are closed 2-manifolds, 0 open and 0 non-manifold edges, with the expected number of pieces, and the peeled parts come out with their expected pieces likewise and sum to the whole within 0.001 % with no overlap and no void. The whole is expected to have one piece per molecule, heavy atoms within 4 Angstrom of each other being one molecule, so three separate rings are not accepted welded through a hair-line neck, nor a connected model pinched apart, while any clean level has the right count. When none does, the whole's count at the level guess becomes the target, or the fewest pieces in the scan when the whole is not clean there, and a pinned level takes its own, with a `one piece per molecule` warning whenever the count differs; a part may have one piece per cluster of its own atoms, normally 1 and 2 for a chain with a break. The accepted level nearest the guess wins; with none, the scan widens once and then the run stops and prints the table. `surface dust`, 20 Angstrom by default (`--dust`), runs on every contour after the surface is actually built: on the whole it removes specks and fills enclosed cavities smaller than the dust size but never removes the whole's largest piece or one that carries a part's main piece, and on the part fields it only fills cavities, so a chain-break tail keeps its colour; a small ligand survives when its chain is a part of its own, and is removed like any other speck when its chain is joined to another in one part. `--level` pins a level, which is still validated.
- Forced voxel step 1 on every surface, contouring at every grid point, and verified it rather than trusting the request: each surface's step is read back inside ChimeraX before export, and a surface at any other step is refused. It is not an option, and `--level-step` is the contour-level increment, not the voxel step. The exported STLs are then read back from disk and checked again for open edges and for pinch edges after vertex welding, and the whole's file for its piece count and non-manifold edges, while the sum against the whole, pairwise overlap and void are measured on the boolean results the files were written from; the report and its JSON carry the scan table, every number, printing notes and a `REPRODUCE` line with every choice pinned. A few pinch edges are normal where the complement's reclaimed shell closes to zero thickness, and slicers repair them; the check warns only above `max(20, 2e-4 * triangles)` per part. Reflection negates the writhe, the linking number, and every other chirality-sensitive invariant, and it is applied to a whole link at once, so the components of a mirrored link stay in register with one another. For an amphichiral knot such as `4.1`, whose shipped conformation measures `+0.15240866875536058`, near zero beside the `8.6` of `8.19`, the mirror measures `-0.15240866875536058` and is the same knot type in a different conformation, not a second knot. A reflected file is written as `<stem>_mirror.xyz`, or `<stem>_mirror_A.xyz` per component under `--split`, and its `#` header records that the coordinates were reflected and on which axis, so a file on disk is never ambiguous about its handedness. `--both` is opt-in rather than the default because `--all --both` writes 1044 files instead of 522. Callers get the same three choices as `extract(..., mirror=False, mirror_axis="z", both=False)`, with `mirror_points(points, axis="z")` reflecting one curve on its own.

- Prefills the phase helper from the main Curve It GUI and transfers the computed phase back automatically.
- Added light-blue `?` help buttons, unit labels, and dynamic enable/disable behavior to the phase helper GUI.
- Renamed the main GUI label from **Helix phase (deg)** to **Phase (deg)**.

## V2.8 - 2026-06-23

- Added `curve_it_lib/generate_helix_xyzV2.py` as a **Generate helical curve...** tool in the Curve It GUI **Tools** area.
- Updated the generator GUI to use Curve It-style bold sections, light-blue `?` help buttons, and optional package icon loading.
- Added a Plane It `--draw-xy-plane` option and GUI control to draw an SVG group/layer named `xy-plane` with a `xy-plane-shape` polygon for the original coordinate plane `z=0`; when SVG depth ordering is enabled, the plane patch is sorted with the same back-to-front rules by mean projected corner depth.
- Updated Curve It version, README, and helper-module documentation for the new circular helix curve generator.

## V2.7 - 2026-06-21

- Changed `--scale-mode none` so it preserves both the PDB/helix length and the curve length, then maps using native PDB/helix axial spacing. Open curves must be at least as long as the PDB/helix principal-axis length; closed curves may wrap periodically.
- Kept `--scale-mode helix_to_curve` as the full-curve distribution mode for an unscaled curve.
- Updated Curve It version, CLI help, GUI help, and README wording for the new scale-mode distinction.

## V2.6 - 2026-06-20

- Added Plane It as a companion GUI/CLI tool via stable launcher `plane_it.py` and versioned implementation `curve_it_lib/plane_itV3_6.py`, adapted from the provided V3.6 projection script.
- Updated `plane_it.py` to discover the newest `curve_it_lib/plane_itV*.py` implementation automatically when future versioned files are added.
- Added **Plane It...** to the Curve It GUI **Tools** area without changing existing Curve It processing behavior.
- Added the supplied Plane It icon at `assets/plane_it_icon.png`.
- Updated Plane It branding in user-facing docstrings, CLI help, GUI title/messages, and projection-basis PDB remarks.
- Updated Plane It's DSSR runner to launch `x3dna-dssr` from the per-input `tmp_file` folder while passing absolute input/output paths, keeping DSSR sidecar files out of the launch directory.
- Updated Plane It defaults: DSSR base-pair line width is now `3.0`, and depth-ordered neighbor-line underlay extra width is now `8.0`.
- Updated README with Plane It GUI/CLI usage, DSSR default-output behavior, blank-line coordinate component handling, and PyInstaller packaging examples.
- Added `curve_it_lib/cal_xyz_local_curvature_torsionV3_1.py` as a Curve It tool for local curvature, regularized torsion, and local writhe-density CSV output.
- Added a dedicated GUI **Tools** area containing **Convert XYZ...** and **Local curvature/torsion...** for current and future utilities.
- Added a quick-loading and quick-running trefoil example to the local curvature/torsion tool: `x=(2+cos(3t))cos(2t)`, `y=(2+cos(3t))sin(2t)`, `z=sin(3t)`.
- Added cursor hover reporting in **View curve** so the plot footer shows normalized path location `u` from `0` to `1` when the cursor is close to the curve.
- Revised `cal_xyz_total_curvature_writheV2.py` to strip duplicated closed-curve endpoints before smoothing/spline fitting and to use normalized chord-length spline parameterization.
- Updated in-memory closed-curve smoothing in `curve_it.py` to strip duplicated final points before smoothing.

## V2.5 - 2026-06-20

- Added component-aware parsing for plain XYZ/txt curve files separated by blank lines; components are labeled `A`, `B`, `C`, and so on.
- Added CLI `--curve-components` selection with support for values such as `A`, `B,C`, `A-C`, and `all`.
- Added GUI component summary and **Select components...** dialog; all components remain selected by default for backward compatibility.
- Updated **View curve** to use `curve_it_lib/view_xyzV3.py`, including component checkboxes plus **All components** and **Selected** view controls.
- Added selected curve component labels to generated PDB `REMARK 900` provenance lines.
- Confirmed molecular XYZ files remain usable as curve inputs and are treated as a single component.
- Kept optional GUI icon loading from `assets/icon.png`; the app still runs if the icon asset is absent.

## V2.4 - 2026-06-17

- Renamed the main script from `curve_naV2.3.py` to `curve_it.py`.
- Moved helper modules into `curve_it_lib/` and updated imports accordingly, while preserving existing helper version suffixes such as `V2`.
- Added `-v` and `--version` support reporting `curve_it V2.4`.
- Added protein-aware grouping: nucleic acid residues use phosphate/sugar/base groups, while protein and other residues use whole-residue rigid groups.
- Updated the GUI title to `AZBMOST Package Module #3 - Curve It: Sculpt PDB Structures Along Any 3D Curve`.
- Added optional GUI icon loading from `assets/icon.png`; the script continues normally if the icon is absent.
- Added a knot-style project icon at `assets/icon.png`.
- Added provenance `REMARK 900` lines at the start of generated PDB files.
- Added light-blue `?` help buttons with pop-up explanations and examples for GUI arguments.
- Added a scrollable run log window at the bottom of the GUI.
- Added the current run's CLI-equivalent command to the GUI run log.
- Added a GUI `Convert XYZ...` tool for coordinate XYZ <-> molecular XYZ conversion.
- Replaced the converter's Yes/No prompt with explicit conversion-direction buttons.
- Improved molecular XYZ curve parsing by explicitly skipping atom-count and comment header lines.
- Reorganized GUI fields to reduce vertical space and narrowed short input fields.
- Restored compact always-visible GUI hints for curve and mapping parameters.
- Bolded GUI section titles for emphasis.
- Added GitHub-ready repository files: `README.md`, `LICENSE`, `requirements.txt`, `.gitignore`, and this changelog.
